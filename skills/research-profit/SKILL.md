# research-profit

新商品開発の利益計算ハブ。**いつでも呼べる。**
現時点で NocoDB に蓄積されたデータを使い、全候補商品の利益を試算・横断比較する。
未確認データは推定値（信頼度付き）で補完する。

## 設計思想

- 確定値があればそれを使う。なければ推定値+信頼度ラベルで計算する
- 「今何がわかっていないか」を可視化して次のアクションを示す
- 全候補を横断比較して「どれを優先して進めるか」を判断できるようにする

---

## Step 0: 対象商品の確認

NocoDB の企画プロセス管理テーブルから全アクティブ候補を取得し、ユーザーに提示。
単一商品のみを計算したい場合はユーザーが指定。

---

## Phase 1: データ収集（NocoDB から）

各候補商品について以下を取得:

| データ項目 | 取得元 | 信頼度 |
|-----------|--------|--------|
| 競合価格帯・中央値 | Amazon競合商品テーブル | ★★★ 実測値 |
| BSR → 推定月販数 | Amazon競合商品テーブル | ★★☆ 推定値 |
| 想定販売価格 | 企画プロセス管理テーブル / ユーザー入力 | ★★☆ 仮設定 |
| Amazon手数料率 | カテゴリー候補テーブル / デフォルト8% | ★★★ 確定値 |
| FBA手数料 | ユーザー入力 / Amazonシミュレーター結果 | ★★☆ 概算 |
| 仕入単価 | 1688商品テーブル（確定）/ ユーザー入力（推定） | ★〜★★★ |
| 広告費率 | 企画プロセス管理テーブル / デフォルト25% | ★☆☆ 仮設定 |

## Phase 2: 利益計算（全候補 × 3シナリオ）

**計算式（1個あたり）:**
```
売上 = 販売価格
Amazon手数料 = 売上 × 手数料率
FBA手数料 = 固定値
広告費 = 売上 × 広告費率
仕入原価 = 仕入単価 × (1 + 関税率 + 代行手数料率)
粗利 = 売上 - Amazon手数料 - FBA手数料 - 広告費 - 仕入原価

月利益 = 粗利 × 月販数
12M累計利益 = 月利益 × 12（立ち上げ3ヶ月は月販数×0.4で補正）
```

**3シナリオ:**
- **ベース**: 月販数・仕入単価ともに中央推定
- **楽観**: 月販数+30%、仕入単価-10%
- **悲観**: 月販数-30%、仕入単価+20%

NocoDB 利益シミュレーションテーブルに保存。

## Phase 3: 横断比較レポート

```
候補商品       | ベース12M利益 | 楽観    | 悲観    | データ信頼度 | 最大の不確実性
スタイA        | ¥540,000     | ¥720k  | ¥280k  | ★★☆ (仕入推定) | 仕入単価未確認
マザーズバッグB | ¥380,000     | ¥520k  | ¥190k  | ★☆☆ (月販推定) | 競合データ未取得
スタイC        | ¥610,000     | ¥830k  | ¥350k  | ★★★ (全確定) | なし → Go判断可
```

**感度分析（主要変数の利益への影響）:**
- 仕入単価 ±¥50 → 月利益 ±¥X
- 月販数 ±20個 → 月利益 ±¥Y
- 広告費率 ±5% → 月利益 ±¥Z

## Phase 4: 次アクション提案

利益改善効果が最大の「未確認変数」を特定して提案:

```
例:
「スタイAは仕入単価の信頼度が低い（推定¥250、幅±¥100）。
 /research-1688 で確認すれば利益試算の精度が大幅に上がり、1位確定の可能性あり。」

「スタイCは全データ確定。悲観シナリオでも¥350k。Go/NoGo 判断が可能。」
```

## AI支援の依頼パターン

| 依頼 | AIの動作 |
|------|---------|
| 「利益計算して」「採算確認して」 | Phase 1-3 実行 → 横断比較レポート |
| 「仕入上限を教えて」 | 粗利率≥20%になる仕入単価の上限を逆算（research-1688の価格フィルタに渡す値） |

| 「感度分析して」 | Phase 2 の3シナリオ + 主要変数の影響を詳細表示 |
| 「スタイAのGo/NoGo判断して」 | 当該商品の全データ確認 → 判断根拠を整理して提示 |
