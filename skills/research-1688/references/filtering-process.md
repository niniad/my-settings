# 1688商品フィルタリングプロセス

3段階で1688商品を絞り込み、サンプル候補を決定する。
全カテゴリ共通の手法。カテゴリ固有の値（価格閾値・除外キーワード等）だけが変わる。

## 全体フロー

```
Stage 1: 客観フィルタ（AI自動）        ~1000件 → ~200件
Stage 2: AI支援スクリーニング（半自動）   ~200件 → ~50件
Stage 3: 手動評価（人間）               ~50件 → ~15件 → サンプル発注
```

**原則: 人間の目視確認は最後のStage 3のみ。** Stage 1-2 でAIが機械的に絞り込むことで、手動評価の対象を最小化する。

---

## Stage 1: 客観フィルタ（完全自動）

利益シミュレーション・工場データから機械的にフィルタリング。

### フィルタ項目

| フィルタ | 算出方法 | 設定タイミング |
|---------|---------|--------------|
| **価格上限** | 利益シミュレーションで粗利率≥20%になる仕入単価 | Phase 3 完了時 |
| **価格下限** | カテゴリの品質担保下限（任意） | Phase 4 開始時にユーザーと決定 |
| **工場年間販売数下限** | 全工場の分布を見て極小を除外 | Phase 4 開始時にデータから算出 |
| **除外キーワード** | 対象外の商品形態（三角巾のみ等） | Phase 4 開始時にユーザーと決定 |
| **MOQ上限** | 初回サンプル取得可能な数量（任意） | 設定する場合のみ |

### 実行方法

1. NocoDB の 1688商品テーブルをSQLiteで直接クエリ（高速）
2. 工場年間販売数は工場単位で集計（工場内全商品の合計）
3. 結果を `stage1_pass` カラムに Boolean で記録

### フィルタ閾値の決定プロセス

```python
# 価格上限: 利益シミュレーションから逆算
# 例: 売価¥2,280、粗利率20%以上 → 仕入単価 ≤ X元
# NocoDB 利益シミュレーションテーブルのシナリオから算出

# 工場年間販売数: 分布の下位を除外
# 全工場の販売数を取得 → パーセンタイルで下限設定（目安: 下位5%を除外）

# 除外キーワード: ユーザーと相談して決定
# 商品タイトル頻出語を集計 → 明らかに対象外の形態を除外
```

## Stage 2: AI支援スクリーニング（半自動）

Stage 1 通過商品に対し、AIで品質・デザインを粗く評価。

### 2-A: タイトル構造化

商品タイトルから属性を機械的に抽出し、構造化フィールドに記録する。

**抽出項目の例（スタイの場合）:**

| 属性 | 抽出キーワード（中国語） | 値の例 |
|------|----------------------|--------|
| 形状 | 360/花瓣/旋转, 圆形, U型, 三角 | 360度回転, U型, 三角 |
| 素材 | 六层纱布, 精梳棉, 纯棉, 华夫格 | 6層ガーゼ, 精梳綿 |
| 防水 | 防水 | あり/なし |
| 規格 | A类 | A類/記載なし |
| 両面 | 双面 | あり/なし |
| スタイル | ins, 韩版, 北欧 | 韓国風, 北欧風 |

**他カテゴリへの適用:**
- スペックマスタの項目名 → 1688タイトルキーワード のマッピングを新規定義
- フォーマットは同じ。キーワード辞書だけが変わる

### 2-B: 重複・類似商品のグループ化

同一工場の類似タイトル商品をグループ化し、代表品のみ残す。

**グループ化ロジック:**
1. 同一工場（店舗名）内でタイトル類似度を計算
2. 形状・素材・価格帯が同じ商品をグループ化
3. 各グループから価格中央値の商品を代表として残す
4. グループ化結果はユーザーに提示（誤グループ化の修正機会）

### 2-C: AI画像スクリーニング（オプション）

商品画像URLが取得可能な場合、Claude Vision で一括評価。

**評価観点:**
- 素材の質感（安っぽさ/高級感）
- 縫製の丁寧さ（写真から判別可能な範囲）
- デザインの独自性（量産品っぽさ vs 差別化可能性）
- セット展開の可能性

**制約:**
- 1688の画像URLが直接アクセス可能でない場合がある
- 写真の品質≠商品の品質（撮影技術の差）
- あくまで参考情報。Stage 3 の手動評価で最終判断

### Stage 2 の記録

結果を以下のカラムに記録:
- `stage2_pass`: Boolean（Stage 2 通過）
- `ai_tags`: Text（タイトルから抽出した属性タグ）
- `ai_note`: Text（AI評価コメント。グループ化・画像評価の所見）

## Stage 3: 手動評価（人間判断）

Stage 2 通過商品（~50件）のみを人間が確認。

### 評価方法

1. NocoDB のフィルタ付きビューで Stage 2 通過商品を一覧表示
2. 各商品の1688ページを開いて確認
3. `手動評価`（1-5）を付与

### 評価基準（参考）

| 評価 | 意味 |
|------|------|
| 5 | サンプル必須。差別化ポテンシャル高い |
| 4 | サンプル候補。品質・デザインが良い |
| 3 | 保留。条件次第で候補になりうる |
| 2 | 見送り。基準を満たすが魅力に欠ける |
| 1 | 対象外。品質・デザインが不適合 |

### サンプル候補の決定

- 手動評価4以上を基本候補とする
- 工場ベースで5~7社、計10~15商品が目安
- 価格帯・デザイン傾向のバリエーションを確保

## NocoDB カラム追加

1688商品テーブルに以下を追加（全カテゴリ共通）:

| カラム名 | 型 | 説明 |
|---------|------|------|
| stage1_pass | Checkbox | 客観フィルタ通過 |
| stage2_pass | Checkbox | AIスクリーニング通過 |
| ai_tags | SingleLineText | タイトルから抽出した属性タグ |
| ai_note | LongText | AI評価コメント |

`手動評価` は既存カラムをそのまま使用（Stage 3 で付与）。

## カテゴリ別パラメータシート

新カテゴリ開始時に以下を定義する。スキル起動時にユーザーと確認。

```yaml
category: スタイ
stage1:
  price_max: 10.0      # 元（利益シミュから逆算）
  price_min: null       # 設定しない場合
  factory_sales_min: 500
  exclude_keywords: []  # 必要に応じて追加
  moq_max: null
stage2:
  title_keywords:       # スペックマスタ項目 → 1688キーワード
    形状: {360: 360度回転, 花瓣: 花弁, 旋转: 回転, 圆形: 円形, U型: U型, 三角: 三角}
    素材: {六层: 6層, 八层: 8層, 纱布: ガーゼ, 精梳棉: 精梳綿, 纯棉: 純棉, 华夫格: ワッフル}
    防水: {防水: あり}
    規格: {A类: A類}
    両面: {双面: あり}
  image_screening: false  # 画像URL取得可能な場合true
```
