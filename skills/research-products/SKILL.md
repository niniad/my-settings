# Amazon Product Research

市場バリデーション → 競合分析・レビュー分析 → 利益シミュレーション → 参入Go/NoGo判断。
最終判断基準: **6か月 / 1年の累計販売利益額の最大化**。

データ取得: **amazon-competitor-analyze スキル**（SP-API + agent-browser）/ 新カテゴリ市場規模のみセラスプ月額契約
NocoDB テーブル定義: [references/tools-and-tables.md](references/tools-and-tables.md)

## ワークフロー

**スキル起動時は必ず企画プロセス管理テーブルを確認し、現在のフェーズとステータスをユーザーに提示してから作業に入る。**

```
Step 0: 対象商品の Base ID を確認 → 企画プロセス管理テーブルで進捗確認 → ユーザーに提示
Phase 1: 市場バリデーション → 参入すべきカテゴリか即時判定
  → ユーザー Go/NoGo
Phase 2: 競合分析・レビュー分析 → 競合の強み弱みと顧客ニーズを構造化
  → ユーザー スペックマスタ確認
Phase 3: 利益シミュレーション → 数値で参入可否を最終判定
  → ユーザー Go/NoGo → amazon-sourcing へ
```

### 進捗管理ルール

- フェーズのステータス変更時は企画プロセス管理テーブルを更新する（ユーザー確認後）
- ステータス: `未着手` / `進行中` / `完了`

## Phase 1: 市場バリデーション

**目的**: この商品カテゴリに参入すべきか即時判定

> **データ取得**: 新カテゴリの市場規模・成長率・独占度・キーワード逆引きはセラスプ月額契約時のみ利用。
> 既存カテゴリの競合データは `amazon-competitor-analyze` スキルで自動取得可能。

| # | タスク | 担当 | 詳細 |
|---|--------|-----|------|
| 1.1 | セラスプ「市場リサーチ」実行（新カテゴリのみ） | 👤 | カテゴリ名を入力、CSVエクスポート |
| 1.2 | 市場データ分析 | 🤖 | CSV読込→市場規模/成長率/独占度を判定 |
| 1.3 | セラスプ「商品リサーチ」実行（新カテゴリのみ） | 👤 | 条件設定（販売数300+、成長率3%+等）、CSVエクスポート |
| 1.4 | 競合商品データをNocoDB登録 | 🤖 | CSVまたはamazon-competitor-analyzeのJSONからAmazon競合商品テーブルに一括登録 |
| 1.5 | 即時除外判定 | 🤖 | 市場規模/ブランド独占度/価格帯で参入可否レポート |
| 1.6 | 法規制・認証の確認 | 🤖 | Web検索でPSE/食品衛生法/関税率を調査 |
| 1.7 | **Go/NoGo判断** | 👤 | AIレポートを見て参入判断 |

**除外基準**: 市場が小さすぎる / 大手寡占 / 法規制クリア不可

## Phase 2: 競合分析・レビュー分析

**目的**: 競合の強み・弱みと顧客ニーズを構造化

> **amazon-competitor-analyze スキルで自動取得可能**: 商品情報・箇条書き・BSR・画像（→Eagle）・レビュー・A+コンテンツ
> セラスプのChrome拡張は不要になった。

| # | タスク | 担当 | 詳細 |
|---|--------|-----|------|
| 2.1 | 競合ASIN一覧を用意（上位10-20商品） | 👤 | ASINリストをメモ |
| 2.2 | amazon-competitor-analyze で商品情報・BSR・画像を取得 | 🤖 | `fetch_catalog.py fetch --asins ... --product {slug}` → JSON + Eagle登録 |
| 2.3 | BSR→推定販売数に変換 | 🤖 | `bsr_to_sales.py estimate` で各商品の月間販売数推定 |
| 2.4 | 販売推移データをNocoDB登録（必要時） | 🤖 | amazon-competitor-analyze JSONからAmazon販売推移テーブルに登録 |
| 2.5 | amazon-competitor-analyze でレビューを取得 | 🤖 | `fetch_reviews.py --asins ...` → reviews JSON |
| 2.6 | レビューをNocoDB登録 | 🤖 | reviews JSONからAmazonレビューテーブルに登録 |
| 2.7 | レビューテキスト分析 | 🤖 | 不満・要望を頻度順抽出→スペックマスタの判断基準・顧客心理に反映 |
| 2.8 | 商品画像はEagleから参照 | 🤖 | Eagle「競合データ/{slug}/{ASIN}/」フォルダ → 画像読み込み |
| 2.9 | 商品画像テキスト解析 | 🤖 | Eagle画像をOCR→訴求ポイント抽出→Amazon商品画像テキストに登録 |
| 2.10 | スペックマスタの定義・優先度設定 | 🤖 | レビュー分析結果からスペック項目と優先度を提案 |
| 2.11 | スペックマスタ確認・調整 | 👤 | AI提案を確認、必要に応じ修正 |
| 2.12 | 競合商品スペック値の登録 | 🤖 | 商品詳細・画像テキストからスペック値を抽出→商品スペックに登録 |

**スペックマスタは amazon-sourcing で以下に活用される:**
- Phase 4: Stage 2 AI支援スクリーニングのタイトルキーワード定義の根拠
- Phase 5-7: 工場回答・サンプル実物のスペック評価スコアの判断基準

## Phase 3: 利益シミュレーション

**目的**: 数値で参入可否を最終判定

| # | タスク | 担当 | 詳細 |
|---|--------|-----|------|
| 3.1 | 1688で候補商品の概算単価を確認 | 👤 | 1688.comで検索、代表的な単価をメモ |
| 3.2 | CPC取得（新カテゴリ: セラスプ逆引き / 既存: SP-API広告データ） | 👤/🤖 | 新カテゴリはセラスプ月額契約時にCSVエクスポート。既存カテゴリはBigQuery広告データから主要KWのCPCを参照 |
| 3.3 | キーワードデータをNocoDB登録 | 🤖 | CSVまたはBigQueryデータからキーワードデータテーブルに登録 |
| 3.4 | 利益シミュレーション作成 | 🤖 | 3シナリオ（ベース/楽観/悲観）。商品単価・為替・FBA手数料・CPC・販売予測を登録 |
| 3.5 | シナリオ比較レポート | 🤖 | 原価/粗利/累計利益を自動算出。感度分析 |
| 3.6 | **Go/NoGo判断** | 👤 | 3シナリオの利益を見て参入判断 |

**除外基準**: 1年累計利益がベースケースで基準以下 / 悲観ケースで赤字

**amazon-sourcing への引き渡し**: Phase 3 Go 時に、利益シミュレーション結果から 1688商品フィルタリングの価格上限（粗利率≥20%になる仕入単価）を算出し、amazon-sourcing Phase 4 の Stage 1 客観フィルタに渡す。

## AI支援の依頼パターン

| 依頼 | 前提（手動） | AIの動作 |
|------|------------|---------|
| 「市場バリデーションして」 | 新カテゴリ: セラスプCSVを用意 / 既存カテゴリ: ASINリストのみ | 市場分析→参入可否レポート |
| 「競合データ取得して」 | ASINリストを用意 | amazon-competitor-analyze → JSON + Eagle画像登録 |
| 「レビュー分析して」 | — | `fetch_reviews.py` → NocoDB登録→不満/要望抽出→スペックマスタ反映 |
| 「利益シミュレーションして」 | 1688概算単価 / 新カテゴリはCPCをセラスプで用意 | 3シナリオ作成→自動計算 |
| 「進捗を教えて」 | — | 企画プロセス管理テーブル→現在フェーズ・次タスク |
