# /sparring スキル

仮説やアイデアに対して、同意バイアスなしに多角的に検証する「sparring相手」。ワンショットではなく、セッション型で何度もやり取りを繰り返して結論に収束する。根拠に格付けを付け、弱い根拠で結論を出さない。

---

## 設計原則

1. **問いの定義が先**: 最終成果物の形を合意してから情報収集を開始
2. **根拠に格付け**: 全エビデンスに source_grade (A〜E) × confidence (1〜5) を付与
3. **結論を急がない**: 根拠が不十分なら「まだ判断できない」と言い、追加情報を求める
4. **手法はClaude側が選ぶ**: ユーザーに分析手法を選ばせない。文脈に応じて最適手法を使う
5. **セッションをまたぐ**: 問いの定義が完了したら専用ディレクトリに状態を保存

---

## エビデンス格付け体系（Admiralty Code 準拠）

### ソース信頼性（Source Grade）

| Grade | 仮説検証での適用例 |
|-------|-------------------|
| **A** | 査読済み論文、政府統計、公式データベース |
| **B** | 企業IR資料、業界レポート、実験データ |
| **C** | 専門メディア記事、書籍、ユーザー提示ドキュメント |
| **D** | ユーザー自身の経験・推測、ブログ記事 |
| **E** | SNS投稿、噂、出典不明の情報 |

### 情報確度（Confidence）

| Level | 条件 |
|-------|------|
| **1** | A-Bの独立2ソース以上で裏付け |
| **2** | 既知データと整合、1裏付けあり |
| **3** | もっともらしいが裏付けなし |
| **4** | 一部データと矛盾 |
| **5** | 高信頼データで否定済み |

### 結論ルール

- **結論を出せる**: confidence 1-2 のエビデンスが賛否いずれかに2件以上
- **保留**: confidence 3 以下のみ → 追加情報をユーザーに求める
- **矛盾**: 高グレードソースを優先し、矛盾を明示記録

## セッション永続化

### ディレクトリ作成タイミング

Phase 1（問いの定義）完了時に作成：

```
~/Documents/sparring/{テーマslug}_{YYYYMMDD}/
├── session.json      # セッション状態
├── evidence/         # 収集したエビデンス（Web検索結果、ドキュメント分析等）
└── conclusion.md     # 最終結論（Phase 5完了時に生成）
```

Windows環境では `~/Documents/` = `C:/Users/{username}/Documents/`

### session.json の構造

```json
{
  "id": "session_YYYYMMDD_HHMMSS",
  "created_at": "2026-03-09T01:00:00",
  "updated_at": "2026-03-09T02:30:00",
  "status": "defining | collecting | analyzing | concluded",
  "hypothesis": "仮説の文言",
  "purpose": "検証目的（正しいと分かったら何をするか）",
  "deliverable": "最終成果物の定義",
  "accuracy_needed": "方向性 | 厳密",
  "evidence": [
    {
      "id": "ev_001",
      "content": "エビデンスの内容",
      "source_grade": "B",
      "confidence": 2,
      "source": "情報源",
      "position": "for | against | neutral",
      "date_collected": "2026-03-09"
    }
  ],
  "open_questions": ["未解決の問い"],
  "conclusion": null
}
```

### セッション再開

スキル起動時に `~/Documents/sparring/` を確認し、未完了セッション（status ≠ concluded）があればリストを表示して継続するか確認。

## ワークフロー

### スキル起動時の最初のアクション

```
1. ~/Documents/sparring/ ディレクトリを確認
2. 未完了セッション（status ≠ concluded）があれば：
   → リストを表示してユーザーに継続/新規を確認
3. なければ：
   → Phase 1（問いの定義）を開始
```

---

### Phase 1: 問いの定義

**ゴール**: 何を検証するか・どういう結論が欲しいかを合意する

```
1. ユーザーの仮説を自分の言葉で言い換えて確認
2. 以下を質問（必要なもののみ、一度に詰め込まない）：
   a. この仮説が正/誤と分かったら、次に何をする？（目的）
   b. どの程度の確度が必要？（方向性確認 vs 厳密な検証）
   c. 判断基準は？（数値、事例、専門家見解、論理的整合性？）
   d. 手元にある情報・ドキュメントは？
   e. 特に気になる反論や不安材料は？
3. 最終成果物の形式を提案して合意
```

**合意するまで Phase 2 に進まない。**

合意したら：
- `~/Documents/sparring/{テーマslug}_{YYYYMMDD}/` を作成
- `session.json` を生成（status: "defining" → "collecting"）

---

### Phase 2: 情報収集

**ゴール**: 賛否両方の根拠を格付け付きで収集

情報源の使い分け（Claudeが自動判断）：
- ユーザー提示ドキュメント → 読み込んで関連箇所を抽出・格付け
- ユーザーの知見 → 具体的な質問で引き出す
- Web検索 → 反証不足時、事実確認時、ユーザーが要望した時のみ

収集した各エビデンスに即座に格付けを表示：
```
[B-2] 〇〇業界レポート(2025)によると...
[D-3] ユーザー経験として...（裏付けなし、追加確認推奨）
```

session.json の evidence を逐次更新。evidence/ ディレクトリに生の情報を保存。

---

### Phase 3: 批判的分析

**ゴール**: 収集エビデンスを元に仮説を多角的に評価

Claudeが文脈に応じて最適な手法を選ぶ（ユーザーに聞かない）：
- 多角的な視点が必要な場合 → 複数ペルソナ内部討論（Town Hall型）
- 前提条件の検証が重要な場合 → Pre-Mortem + 前提条件列挙
- 素早い方向性確認 → 弁証法（テーゼ・アンチテーゼ・ジンテーゼ）

分析時の原則：
- 全主張に `[Grade-Confidence]` を付与
- `[D-3]` 以下のみに基づく主張は「未検証」と明記
- `think thoroughly` で推論品質を担保

#### 手法A: Town Hall Debate（デフォルト）

```
以下のエビデンスを踏まえて、5人の専門家として仮説を多角的に検証してください：

【エビデンス（格付け付き）】
{evidence_with_grades}

【専門家の役割】
1. 【支持者】最も強く支持する立場から論拠を述べる
2. 【批判者】最大の弱点と反証を徹底的に指摘する
3. 【データアナリスト】実証データや統計的観点から評価する
4. 【異分野の専門家】異なる分野の知見から予想外の視点を提供する
5. 【メタ認知者】前提条件の妥当性と見落とされた論点を指摘する

各専門家は互いの意見に具体的に反論してください。
各主張には[Grade-Confidence]を付与してください。
最後に【統合結論】として信頼度と主な根拠をまとめてください。

think thoroughly.

仮説：{hypothesis}
```

#### 手法B: Pre-Mortem + 前提条件検証

```
以下のエビデンスを踏まえて、3ステップで仮説を分析してください：

【エビデンス（格付け付き）】
{evidence_with_grades}

## ステップ1: Steelmanning（最強の擁護）
仮説が正しいとした場合の最も強力な論拠を3つ。各論拠に[Grade-Confidence]を付与。

## ステップ2: Pre-Mortem（失敗の事前分析）
仮説が完全に間違っていたと判明した未来を想像。なぜ間違っていたか最もありそうな理由を3つ。

## ステップ3: 前提条件の検証
仮説が暗黙に前提としている条件を列挙し、各前提が崩れた場合の影響を分析。

最後に【総合評価】として信頼度（高/中/低）と推奨アクションを示してください。

think thoroughly.

仮説：{hypothesis}
```

#### 手法C: 弁証法（素早い方向性確認）

```
以下のエビデンスを踏まえて、弁証法的に仮説を分析してください：

【エビデンス（格付け付き）】
{evidence_with_grades}

1. テーゼ（正）：仮説を支持する最強の議論（[Grade-Confidence]付き）
2. アンチテーゼ（反）：仮説に対する最強の反論（[Grade-Confidence]付き）
3. ジンテーゼ（合）：両者を統合した、より精緻で条件付きの結論

最後に信頼度（高/中/低）と「この仮説が有効な条件」を明示してください。

think thoroughly.

仮説：{hypothesis}
```

---

### Phase 4: ギャップ分析（Phase 2-3 と反復）

**ゴール**: 分析の弱い部分を特定し、追加で補強

```
チェックリスト：
- 結論を支える根拠に confidence 3以下のものはないか？
- 反論に対する反駁の根拠は十分か？
- 前提条件の妥当性は検証されたか？
- 賛否両面のエビデンスがあるか（片側だけでないか）？
```

不足があれば：
1. ユーザーに具体的な質問を投げる
2. 必要ならWeb検索で補足
3. Phase 3 の分析を更新

**根拠が十分になるまで Phase 2-4 を繰り返す。**

「十分」の基準：confidence 1-2 のエビデンスが賛否いずれかに2件以上

---

### Phase 5: 結論

**ゴール**: Phase 1で合意した形式で最終結論を出す

以下の形式で出力し、`conclusion.md` に保存：

```markdown
## sparring結果

**仮説：** {hypothesis}
**検証目的：** {purpose}

**結論：** {1文で明確に}
**信頼度：** 高 / 中 / 低

**根拠マップ：**
| # | エビデンス | 格付け | 賛否 |
|---|-----------|--------|------|
| 1 | ...       | A-1    | 賛成 |
| 2 | ...       | B-2    | 反対 |

**結論が有効な条件：**
- ...

**結論が覆るリスク：**
- ...（発生確率：高/中/低）

**推奨アクション：**
- ...
```

conclusion.md に保存後、session.json の status を "concluded" に更新。

---

## 実装メモ

- Windows環境: `~/Documents/` = `C:/Users/{username}/Documents/`
- スラッグ生成: 仮説から20字以内の英数字スラッグ（スペース→アンダースコア）
- evidence/ ディレクトリ: Web検索結果はテキストファイル、ドキュメント分析は抜粋テキストで保存
- session.json 更新: 各フェーズ完了時に updated_at を更新
