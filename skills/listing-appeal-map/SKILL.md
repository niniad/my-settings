# listing-appeal-map スキル

Amazon.co.jp 商品画像の訴求マップ（appeal-map.md）を設計するスキル。
`brand/image-design-process.md` の6ステップ + Evaluator Agent 7軸評価で完成させる。

## 前提条件

- 競合分析（`/amazon-competitor-analyze`）が完了していること
- 競合データ: `listings/products/{slug}/competitor-data/competitor-analysis.md`
- **既存アセット確認必須**: appeal-map設計前に以下を確認する
  - 既存サブ画像（Eagle等）→ 訴求内容・機能仕様の正確な把握に使う
  - 既存動画 → 最終スロットとして使用可否を判断
  - 既存メイン画像 → Sub1候補として流用できるか確認

## 実行手順

### STEP 0: 既存アセット棚卸し（新規追加）

appeal-map設計の前に必ず実施する。

1. **Eagle等の画像管理ツールで既存サブ画像を全確認**
   - 現行サブ画像から機能仕様（ポケット数・素材・特殊機能）を正確に読み取る
   - 訴求禁止事項は「ない」と思い込まず、既存画像で実際の仕様を確認してから記載する
   - 既存動画があれば最終スロット（Video）として記録する

2. **Amazon モバイル閲覧率を考慮した優先度設定**
   - Sub1-3（閲覧率75-100%）: USP・驚き・納得の核を集中させる
   - Sub4-5（閲覧率45-55%）: 差別化機能の証拠
   - Sub6-7（閲覧率20-30%）: 詳細確認ニーズへの対応
   - Video（閲覧率10-15%・タップ必要）: 感情クローザー。画像スロットとは別カウント

3. **訴求禁止事項を確定してから設計開始**
   - 「機能があるかどうか不明」のまま禁止事項に追加しない
   - 既存画像・仕様書で確認してから記載する

4. **コピーに書く動作・体験の事実確認**
   - コピー案に「〜できる」「〜取り出せる」等の動作を書く前に必ず確認:
     - どのポケット/どの操作か特定できているか
     - 実際の製品でその動作が可能か（例: 抱っこ中に片手でメインポケットからおむつは取り出せない）
     - 競合の訴求コピーを参考にする場合も自社製品への適用可否を検証する
   - 事実確認できないコピーは「〜しやすい設計」「大きく開く」等の状態表現に留める

### STEP 1: 前提整理シート

`competitor-analysis.md` を読み込み、以下を抽出する。
- ターゲット・検索行動・悩み Top3
- 競合との差別化ポイント（USP）
- 購入前の不安
- **テーブルステークス**: ④-Bから抽出。全項目がどこかの画像でカバーされていることを確認する（差別化にはならないが、不在は致命的な要素）
- **USP検証結果**: ④-Dの3段階評価（検証済USP / 認知済だが差別化弱い / 未認知USP）に基づき、「検証済USP」をコアメッセージの根拠に使用する。「未認知USP」は訴求方法の見直しが必要
- **分析の限界**: ④-Fを確認し、appeal-mapが「推測レベル」のInsightに過度に依存していないかチェックする

### STEP 2: CTR設計（メイン画像 + タイトル先頭30文字）

スマホサムネイルで勝てるメイン画像コンセプトを設計する。

### STEP 2.5: キービジュアル壁打ち（Sub2）

Sub2（最重要サブ画像）の構図・感情・メッセージを具体化する。

### STEP 3: 感情動線設計

Sub1〜Sub8 の流れを「導入→共感→解決→証拠→安心」で設計する。

### STEP 4: 各画像の4レイヤー設計

各画像に Hook / Benefit / Reason / Proof を割り当てる。

#### 1枠使用の妥当性チェック

各Sub画像に割り当てる前に以下を確認する:

| 問い | NGの例 |
|------|--------|
| その機能は競合との差別化になるか | ファスナーの滑らかさ（競合も同程度） |
| caption補足で済まないか | ショルダー幅は数値をcaptionに書けば伝わる（ただし悩みTop訴求なら独立1枚の価値あり）|
| 閲覧率（位置）に見合う訴求価値があるか | Sub6-7（閲覧率20-30%）に弱い訴求を置かない |
| 1枚で完結する訴求か | 複数機能を詰め込んでいないか |

判断に迷う場合: 「この画像が1枚もなくても購入判断に影響しないか」を問う。影響しないならA+に移動するか削除する。

### STEP 4.5: コピーライティング

ベンチマーク分析（competitor-data/benchmark-pages.md）から導出したルール。

#### メインコピーの原則

**動詞・変化で終わる**（状態記述にしない）
- 弱い: `軽量です` `大容量です` → 強い: `ラクになる` `防ぐ` `さっと一拭き`
- メインコピーは「読んだ人の頭に動作・変化の映像が浮かぶ」かどうかで判定する
- 25字以内（スマホで1秒以内に読める長さ）

#### サブコピーの原則

**メインコピーの根拠を示す**
- メインが体験 → サブは事実・数値: `しっとりもちもちに保湿` → `胎脂に近い高保湿成分と天然由来の特許成分配合で`
- メインが事実 → サブは体感・場面: `僅か150gで持ち運びが便利なコンパクト設計` → `軽量スマホとほぼ同等のサイズ感`

#### 画像役割別のコピーの型

| 画像の役割 | メインコピーの型 | ベンチマーク実例 |
|-----------|----------------|----------------|
| 感情フック（キービジュアル） | 悩みの現実→変化を宣言 | `抱っこがラクになる！`（コペルタ） |
| 問題の再定義 | 悩みに名前を付けて構造化 | `老け見えの正体は、「4つのエイジシグナル」だった`（クワトロボタニコ） |
| ファクト証明 | 数値＋身近な物で体感変換 | `僅か150gで…軽量スマホとほぼ同等のサイズ感`（ネックピロー） |
| 使用シーンBenefit | 具体的な動作の結果 | `確かな撥水性で汚れをさっと一拭き。`（whitelapin） |
| 理由・ストーリー | なぜそうなのかの根拠 | `意匠権取得の 革命的ネックピロー`（ネックピロー） |
| 機能グリッド | 機能名+1行Benefit | `好みの硬さにポンプで細かく調節可能`（ネックピロー） |
| ライフスタイル・ブランド | 購入後の未来像 or 想い | `がんばるパパママに安心と楽ちんを届けたい`（コペルタ） |

#### 言葉の磨き方

**1. 悩みは「あるある」レベルまで具体化する**
- 弱い: `お悩みありませんか？`
- 強い: `汚れが落ちなかったりカビが生えたり シワシワになってつけさせるのが恥ずかしい`（whitelapin）
- ターゲットが「それそれ！」と感じる具体的な場面を描写する

**2. 数字は「体感変換」とセットで使う**
- 数字だけ: `150g` → ふーん
- 体感変換付き: `150g → 軽量スマホとほぼ同等のサイズ感` → えっ、そんなに小さいの
- 数字は「驚き」を生むための入口。身近な物・動作に置き換えて着地させる

**3. オノマトペは1画像に1つ、大きく**
- `軽〜いっ!!` `ピタっと！` `しっとりもちもち` `す〜っと浸透` `さっと一拭き`
- 体感を音で表現する切り札。乱用すると安っぽくなる

**4. 引き算で磨く**
- 最初に書いたコピーから「なくても意味が通じる言葉」を削る
- 説明的な接続詞（「そして」「また」「さらに」）は基本不要
- 形容詞を2つ重ねない。動詞か具体名詞で映像を見せる

**5. リズムを整える**
- 対句はリズムを生む: `荷物を増やさず、上質な眠りを。`（ネックピロー）
- 短い文で「。」切り → 断言。インパクト
- 体言止めは1コピーに1回まで

**6. 文字種で温度を操作する**
- ひらがな多め → やわらかい・親しみ（育児系に合う）
- 漢字多め → 硬い・信頼感（スペック説明向き）
- カタカナ → 軽さ・異質感（アクセントに使う）

#### NG
- スペック羅列をメインコピーにしない
- 「最高」「究極」「圧倒的」等の根拠なき修飾語（ただし意匠権等の裏付けがあれば可）
- 全画像を同じトーンにしない（動線の感情変化が消える）
- 1画像に3つ以上の訴求

#### 参照
- ベンチマーク実例: `ec/products/{slug}/competitor-data/benchmark-pages.md`

### STEP 5: 訴求内容を appeal-map.md に記述

出力先: `listings/products/{slug}/appeal-map.md`

フォーマット（`listings/brand/image-design-process.md` 参照）:
- 前提整理テーブル
- 全体構成テーブル（見出しは `Sub X枚 + 動画 + A+ Yモジュール` と全要素を明記。動画スロットも行に追加する）
- 各Sub・A+ の詳細仕様（レイアウト・写真素材指示込み）

### STEP 5.5: Evaluator Agent 評価（Generator-Evaluator パターン）

Agent tool で `subagent_type=general-purpose` の別エージェントを起動。

**Evaluator に渡すコンテキスト:**
```
- listings/products/{slug}/competitor-data/competitor-analysis.md
- listings/products/{slug}/appeal-map.md
- listings/brand/image-design-process.md
```

**評価7軸**（各10点・合計70点・閾値50点）:

| # | 軸 | チェック内容 |
|---|-----|-------------|
| 1 | 競合差別化 | competitor-analysis.md の差別化ポイントが反映されているか |
| 2 | コアメッセージ一貫性 | 「1商品1メッセージ」が全画像を貫いているか |
| 3 | 感情動線 | Sub1→Sub8 の並び順に心理的な流れがあるか |
| 4 | スマホ3秒テスト | Sub1-3 だけで「誰の / 何が良い / 何が違う」が伝わるか |
| 5 | Benefit vs Feature | 各画像に顧客ベネフィットがあるか |
| 6 | 不安カバー率 | 「購入前の不安」がすべてどこかで解消されているか |
| 7 | 訴求禁止事項 | appeal-map.md の禁止事項に抵触していないか |

閾値未達 → 改善 → 再評価（最大2-3回）→ 閾値達成後にユーザー承認。

### STEP 6: セルフチェック

```
□ コアメッセージが全画像を貫いているか
□ スマホで最初の3枚（Sub1-3）だけ見て「誰の / 何が良い / 何が違う」が分かるか
□ 各画像に Benefit があるか（機能説明だけの画像がないか）
□ 感情動線が途切れていないか
□ 購入前の不安がすべてどこかの画像でカバーされているか
□ 訴求禁止事項に抵触していないか
□ サブ画像だけで購入判断の8割が完結するか
```
